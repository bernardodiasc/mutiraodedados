# Plano — v0.6.0: experiência de importação padronizada

> Escopo vigente no [ROADMAP.md](../../ROADMAP.md); resultado migra para o [RELEASES.md](../../RELEASES.md) ao fechar.

## Por quê

O objetivo do projeto é importar o histórico completo de todas as fontes suportadas com a **mesma experiência**: os mesmos cuidados, o mesmo histórico, a mesma cobertura, os mesmos sinais e a mesma limpeza — respeitando que cada API tem regras e schemas próprios. As releases v0.3.0–v0.5.0 padronizaram o retry e a retomada; esta padroniza o que o operador vê e a confiabilidade do orquestrador.

O "só cliente/job": a linha em `importacoes` é gravada pelo navegador via `registrarTentativa`, uma por job — os botões diretos do painel não registram nada, e as rodadas individuais não aparecem.

## Frentes

1. **Histórico server-side** — `src/lib/data/historico.server.ts`, um helper que grava a linha de rodada no fim de cada server function retomável: fonte, escopo, ano/mês (para a matriz de cobertura), contagens, erros, duração e **motivo de parada** (fim dos dados, orçamento de tempo, teto de subrequisições). Consulta vazia gera linha com zero — é o marcador de "consultado, sem dados". Adotado por CEAP, CEAPS, PNCP, Transferegov e proposições; essas fontes entram no conjunto de auto-log do job builder, que para de duplicar pelo cliente.
2. **Matérias e votações do Senado retomáveis** — um item (matéria/votação) por passo do runner, com custo por subrequisições, mesmo desenho das proposições.
3. **Orquestrador** — renovação de sessão por proximidade de expiração do JWT; re-tentativa única, ao fim do lote, dos jobs que falharam com erro transitório (`TRANSIENT:`), com registro no resumo.
4. **Contrato de fonte + guardas** — checklist e matriz em `docs/importacao.ia.md`; teste-guarda garantindo que `FONTES_LIMPEZA` cobre toda tabela `*_cache` (lista-espelho, como o teste do catálogo de sinais).

## Decisões tomadas

- **Uma linha por rodada, não por job.** O Histórico passa a mostrar cada rodada com seu motivo de parada — é o que torna a retomada auditável. A matriz de cobertura não muda: a RPC `cobertura_tentativas` agrega por (fonte, escopo, ano, mês), então várias linhas no mês colapsam numa célula.
- **Votações da Câmara ficam como estão** (exceção justificada): a importação já é por item (`importarVotacaoUnica`), idempotente e chunked pelo cliente; uma linha de rodada por votação seria ruído. O log de job pelo cliente permanece só para ela.
- **Sinais para proposições/votações/matérias ficam no backlog** (v0.7.0+): criar regra de sinal é trabalho editorial (catálogo, triagem, metodologia pública), não infraestrutura — misturá-lo aqui diluiria as duas coisas.
- **`ano/mes` derivados da janela quando ela cabe num mês** (PNCP, Transferegov, votações Senado); âncora `mes = 1` para fontes anuais (proposições, matérias), como a matriz já espera.
