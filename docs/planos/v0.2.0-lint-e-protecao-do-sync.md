# Plano — v0.2.0: lint verde, código morto e proteção do sync

> Escopo vigente no [ROADMAP.md](../../ROADMAP.md); resultado migra para o [RELEASES.md](../../RELEASES.md) ao fechar.

## Por quê

A v0.1.0 destravou os testes, mas o `bun run lint` seguia falhando com milhares de erros de formatação pré-existentes — um check obrigatório que ninguém conseguia usar como sinal. Sem lint verde, as releases de estabilização de importação (v0.3.0 em diante) não teriam como distinguir regressão de ruído. Junto vão duas dívidas pequenas e independentes: código morto exposto e a falta de proteção mecânica do espelho público.

## Frentes

1. **Lint verde** — formatação em massa com Prettier, isolada em commit mecânico, mais a correção dos erros remanescentes.
2. **Código morto** — remover as duas server functions de QA sem caller.
3. **Proteção do sync** — impedir que o espelhamento reverta contribuição externa em silêncio.

## Decisões tomadas

Registradas aqui para não serem re-decididas depois.

- **Formatação em commit separado.** O reformat mecânico (327 arquivos) foi commitado sozinho, antes das correções semânticas, para que os diffs seguintes fiquem legíveis. O hash está em `.git-blame-ignore-revs` para o `git blame` pular o commit.
- **`.prettierignore` alinhado ao ESLint.** Os dois passaram a ignorar a mesma lista de tooling e caches (`.claude/worktrees`, `.wrangler`, `.tanstack`, `.lovable`). Antes, worktrees antigos respondiam por ~9 mil erros que não são código do produto.
- **Skills continuam sendo formatadas.** O Prettier toca os `SKILL.md` dos dois diretórios espelhados; como é determinístico, os espelhos seguem idênticos byte a byte. Verificado com `diff -rq` após o reformat, e o check faz parte dos critérios de aceite.
- **`any` justificado em vez de tipo inventado.** Quatro escapes permanecem, cada um com `eslint-disable-next-line` e o motivo na mesma linha: nome de tabela dinâmico contra o `Database` gerado do Supabase (3×) e `.or()` ausente no tipo do builder. O CONTRIBUTING.md permite `any` **com** justificativa; inventar tipos estruturais para o cliente do Supabase seria pior. O `any` de fixture de teste virou cast estrutural em `Contestacao`.
- **Warnings não bloqueiam.** Os 16 warnings remanescentes são o padrão shadcn/ui (componente e constante de variantes no mesmo arquivo) e um `exhaustive-deps`. O critério de aceite é **zero erros**; mexer nos componentes shadcn para calar warning de fast refresh seria alterar código funcionando sem ganho.
- **Marcador do sync por tag de release.** A detecção de commits não portados usa a última tag alcançável do `main` público, com o assunto `sync ...` como alternativa para o histórico anterior às tags. Tag é criada pelo mantenedor no fechamento — mais confiável que texto de mensagem, que um contribuidor poderia reproduzir sem querer.
- **A proteção aborta por padrão.** Sincronizar por cima de contribuição não portada é perda de trabalho de terceiro, então o default é abortar. A flag `--allow-unported` existe para o caso deliberado, e avisa em amarelo.
