# Plano — v0.7.0: `/cobertura` completa + IBGE como fonte + qualidade visível

> Escopo vigente no [ROADMAP.md](../../ROADMAP.md); resultado migra para o [RELEASES.md](../../RELEASES.md) ao fechar. Três frentes + migration — daí este plano, conforme o WORKFLOW.

## Por quê

Nos testes manuais da v0.6.0 o mantenedor apontou fontes e dados faltando em `/cobertura`. O levantamento confirmou e dimensionou; de carona, esta release puxa de volta o escopo de qualidade do plano original (UI de lacunas + banners), deixando a plataforma com o ciclo completo: importar → medir cobertura → sinalizar qualidade → curar lacunas.

## Frente 1 — `/cobertura` completa e legível

**Levantamento (2026-08-20).** Dos 17 ids que gravam rodada (`FONTES_COM_HISTORICO` em `src/lib/data/fonte-rotulos.ts`), a página pública mostra 14. Faltam:

| id             | RPC                            | Situação                                      |
| -------------- | ------------------------------ | --------------------------------------------- |
| `camara_props` | `cobertura_camara_proposicoes` | RPC existe — só o admin a consome             |
| `senado_mat`   | `cobertura_senado_materias`    | RPC existe — só o admin a consome             |
| `orgaos_siafi` | — (cadastro)                   | entra como cadastro, `orgaos_cache` + updated |

**Desenho.** A lista de fontes sai da função e vira catálogo puro (`src/lib/data/cobertura-catalogo.ts` — id, título, descrição, rota, granularidade), no padrão de `fonte-rotulos.ts`. Teste-guarda: todo id de `FONTES_COM_HISTORICO` presente no catálogo, e todo id do catálogo com rótulo — a mesma lista-espelho de limpeza e sinais. A server function consome o catálogo; texto de fonte deixa de morar em dois lugares.

## Frente 2 — IBGE como fonte de primeira classe

Hoje a lista de municípios é buscada no navegador a cada uso (`IbgeCombobox`) e a de UFs é constante no código. Vira fonte sob o contrato:

- Migration: `ibge_municipios_cache` (código, nome, UF, updated_at) com GRANT + RLS de leitura pública (dado público, tabela alimentada só pelo admin).
- Ingest retomável (`rodarComOrcamento`, um passo = uma UF, 27 passos) + linha de rodada com id `ibge` (rótulo no `FONTE_LABEL`).
- Entrada em `FONTES_LIMPEZA`, cobertura como cadastro no catálogo da frente 1, janela não se aplica (cadastro vigente).
- `IbgeCombobox` passa a ler do cache com fallback para a API do IBGE quando o cache está vazio.

## Frente 3 — Qualidade visível

**`/admin/lacunas`** — UI para as funções órfãs de `src/lib/lacunas.functions.ts` (`criarLacuna`, `atualizarLacuna`, `converterFindingEmLacuna`), fechando o fluxo de `docs/dominios/laboratorio-civico.md`: listar lacunas (com filtro tipo/ciclo/publicada), criar manualmente, editar ciclo/publicação, e converter finding → lacuna a partir dos findings abertos.

**`QualidadeBanner` em 4 fichas** — fornecedor, órgão, deputado e senador. O banner atual é por entidade exata (`fonte`, `entidade_tipo`, `entidade_id`); as 4 fichas são **agregados**:

| Ficha             | Como achar os findings                                                |
| ----------------- | --------------------------------------------------------------------- |
| fornecedor (CNPJ) | ids de `contratos_cache` por `fornecedor_cnpj` → findings de contrato |
| órgão (cod SIAFI) | ids de `contratos_cache` por `orgao_cod` → findings de contrato       |
| deputado (id)     | `qa_findings` com `fonte='camara_ceap'` e `detalhes->>'deputado_id'`  |
| senador (id)      | `qa_findings` com `fonte='senado_ceaps'` e `detalhes->>'senador_id'`  |

Nova server fn `findingsPorAgregado` cobre os 4 casos; o container do banner ganha o modo agregado sem quebrar o modo atual.
